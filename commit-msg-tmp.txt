trace-fusion: 融合交付形状改造（首跑实测：模型谎称已写文件 + 野路径写盘）

根因（首跑 tfl-20261103-192444-c7e2 实测，三次融合尝试）：
融合者被运行时排除 write/edit（只读强制），但提示词要求它「把 fusion.md 写出来」
⇒ 它用 bash 重定向/tee 自己写盘，并把路径写丢了个点（`.pi` 写成 `pi`），落到主仓外；
最后一条回复只有 123 字符的「File written: …」。判据当时只看「文件是否存在于期望路径」
⇒ 正确地判 failed，但**没有任何机制阻止它写盘**，也没有机制把「正文不合格」与
「盘上有旧产物」区分开。

改了什么：
1. **交付形状改为「回复正文 = 交付物，harness 落盘」**（fusion-dispatch.ts）
   - `captureFusionReport()`：从 stdout json 流取最后一条 assistant 正文，校验六节
     （`FUSION_REPORT_SECTIONS`：采纳结论/分歧与裁决/证据核验/不可采信项/后续行动/可复跑附录），
     合格才 `writeFileSync(outputPath)`；不合格返回 shape（缺几节 + 首 120 字符）。
   - 判据链：exit≠0 ⇒ failed；exit=0 且正文不合格 ⇒ failed（不落盘）；
     合格且产物新鲜 ⇒ completed。旧版 `!existsSync(outputPath)` 才跑 capture
     ⇒ 盘上有旧 fusion.md 时直接跳过校验，半截旧文件会被判 completed（夹具实测踩到）。
   - spawn env 透传 `PI_TRACE_FUSION_FUSION_RUN` / `PI_TRACE_FUSION_FUSION_DIR`（守卫的合法落点）。
2. **提示词**：删除「回复只要文件路径」（旧形状诱导谎称已写文件），改为
   「全文写进最后一条回复正文 + 不要自己写文件」。
3. **lane-bash-guard 写盘落点拦截**（首跑真实缺口）：
   - `findStrayWriteTarget()` 识别 `>` / `>>` / `tee` / `dd of=` 的绝对写盘目标，
     不在 artifactDir 内 ⇒ 拦截；只读命令（`grep /path/file`）放行（首版误拦 grep，已修）。
   - 接线修复：这段原先写在 `if (isShell) { … return … }` **之后** ⇒ 对 bash 命令永不可达。
     现在移到 return 之前，并给 NATIVE_SCAN 分支加 `!isShell` 防重复判定。
   - index.ts 注册面覆盖 fusion 子会话（`isLane: isTraceWorker() || PI_TRACE_FUSION_FUSION_DIR`）。
