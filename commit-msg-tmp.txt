trace-fusion: 融合交付边界重划——给 write 但落点锁死到本 run 产物目录（第四次实测：禁写只造成幻觉）

根因（首跑 tfl-20261103-192444-c7e2 四次融合实测）：
2026-11-02 #1 把 write/edit 全部运行时排除（只读强制），但提示词要求它交付 fusion.md。四次读数：
- 第 3 次：它用 bash 重定向写盘，把 `.pi` 写成 `pi`，在主仓外造出野文件（6806 字节六节齐全的真报告）。
- 第 4 次（14:32:23Z，新判据下）：exit=0，回复 591 字符「融合报告已完成。六节结构完全符合规格（185 行）」
  ——而它根本没有写工具，盘上零产物。**禁写没有消除写盘行为，只是把交付变成了幻觉。**

改了什么：
1. **能力/落点分离**（fusion-dispatch.ts）：`FUSION_EXCLUDE_TOOLS` 移除 `write`、**保留 `edit`**
   （edit 能改仓内已有文件，write 只能造新文件且落点受控）。安全从「无写能力」改为
   「写能力 + 落点机械门」。
2. **write/edit 落点锁**（lane-bash-guard.ts 新增 `findStrayWriteToolTarget()`，注册线接线）：
   绝对路径不在 `artifactDir` 内 ⇒ 拦截（`.pi`→`pi` 这种野路径实测可识别）；
   相对路径交 cwd 约束不在本层拦；只读工具不受影响。
3. **判据链重排**：`exit=0` ∧ 产物新鲜 ∧ 文件六节齐全 ⇒ completed（写明「由融合者写入」）；
   产物新鲜但六节不齐 ⇒ failed 并列出缺哪几节；无产物 ⇒ 走 stdout 正文兼平通道
   （合格则 harness 落盘，不合格 ⇒ failed 且理由同时写明「盘上无产物」+ 回复形状 + 陈旧产物 mtime）。
   新增 `fusionFileSections()` 作为文件侧六节判据。
4. **提示词**：改为「写盘只允许一个路径 = outputPath」+「不得声称『报告已完成』而没真的调用 write」。

怎么验证：
- 夹具新增两条真实形状：① 融合者真的 write ⇒ completed 且理由写明写入者；
  ② 第四次实测形状（回复「报告已完成，185 行六节齐全」+ 盘上零产物）⇒ failed、不落盘、理由带回复形状。
- 守卫夹具：write 越界 ⇒ 注册线 block；写进 artifactDir ⇒ 放行；`.pi`→`pi` 野路径可识别；相对路径/只读工具放行。
